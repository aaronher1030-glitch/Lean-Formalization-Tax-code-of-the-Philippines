# Generated harness files

`Harness.lean` and `BenchCheck.lean` are **generated**, not hand-written:

- `tools/make_benchmark.py` writes `BenchCheck.lean` (one `#eval` per benchmark
  case) and compiles it to cross-check the Python ground truth against the
  verified Lean definitions;
- `tools/run_harness.py` writes `Harness.lean` (one `CertT` literal per engine
  certificate) and compiles it so the verified checker `checkT` is the only
  judge of every engine output.

They are gitignored because the tools regenerate them on every run. To
reproduce the benchmark and the engine study from a fresh clone:

```bash
export LEAN=/path/to/lean.exe     # or lean on PATH via elan
python -X utf8 tools/make_benchmark.py
python -X utf8 tools/run_harness.py
```

The election study and the loophole study generate three more files the same
way: `BenchCheck8.lean` (`tools/make_benchmark8.py`, 64 dual-agreed truth
rows), `Harness8.lean` (`tools/run_harness8.py`, 512 `Cert8` certificates
judged by `check8`) and `LoopholeCheck.lean` (`tools/loopholes.py`, 11
exploiting certificates judged by both checkers). All are gitignored and
regenerated on every run.

`Findings.lean` is generated by `tools/findings.py`: one theorem per finding
(274 in total), each with its own `#print axioms` audit. It is gitignored and
regenerated on every run; the script writes `data/findings.csv` and
`FINDINGS.md` only after the kernel accepts every theorem and the audit
shows only `propext`.
